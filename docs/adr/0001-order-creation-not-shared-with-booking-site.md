# 櫃檯建單流程不與官網訂車流程共用，只共用「合約檢視與簽署」

admin 的建立訂單改為 `/orders/new` 單頁 mat-stepper 時，我們考慮過把它做成共用模組直接給官網（apps/booking）使用，最後決定不共用流程容器，只把自成一體的「合約檢視與簽署」抽成共用元件。理由是兩邊實測只有約 6/20 的欄位重疊（車輛、租期、報價與姓名電話 Email），櫃檯專屬的身分別、國籍、保險、訂金、款項登記、內部備註，與官網專屬的優惠碼、夥伴折扣、車輛篩選，會讓共用元件充滿依情境切換的分支；而且兩邊的形態刻意相反——官網是四個可分享、可重新整理的網址頁（論證見 `docs/architecture/04-booking-flow.md`），櫃檯是單頁精靈。

## Consequences

- 將來若要共用，應共用的是「步驟內容元件、表單定義、送出介面（gateway）」這一層積木，而不是外層流程容器。櫃檯流程已以不依賴 admin 專屬 store 的方式撰寫，預留此路徑。
- 官網訂單目前不會產生合約版本，所以官網端即使接上共用的簽署元件也無東西可簽；合約由誰、何時產生屬於待業主確認的營運規則。
