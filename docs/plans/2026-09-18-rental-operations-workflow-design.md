# 租車營運工作流與帳務 UX 設計

**日期：** 2026-09-18  
**狀態：** 已確認  
**範圍：** `apps/admin` 的新增訂單、證件、付款、合約、取還車、取消退款與首頁工作清單；本輪維持前端 MVP，不串真實金流、OCR、雲端圖檔或 Email 服務。  
**後端交接：** `docs/plans/2026-09-18-rental-operations-backend-handoff.md`

## 1. 背景與目標

目前管理端已能建立會員與訂單，也已有 `paymentMethod`、`pending_payment` 等欄位，但付款狀態和履約狀態混在一起，首頁取／還車清單無法回答下列現場問題：

- 客人已付多少、還欠多少、訂金是否足夠？
- 本次付款是現金、刷卡、LINE Pay、轉帳或混合付款？
- 身分證、駕照與外國旅客駕駛資格是否已核對？
- 最新租賃合約是否已簽署？
- 現在是否可以交車；不能交車的原因是什麼？
- 還車是否逾時、油量／電量是否不足、需補多少費用？
- 取消時應退多少、違約金多少、是否轉成保留金？
- 業者無法交車時，是否已嘗試調車、升等或合作同業轉單？

本設計把訂單改造成可執行的營運工作流，同時保留目前純前端 repository 架構，讓後端之後能逐一接管外部服務。

## 2. 設計原則

1. **付款與履約分離。** 訂單狀態不代表付款狀態，付款狀態由金額與交易紀錄推導。
2. **資料保留而非覆寫。** 收款、退款、合約、證件、費用調整與主管覆核都保留歷史。
3. **首頁只回答下一步。** 工作清單顯示阻擋原因、待辦與快捷操作，完整資料在訂單工作區處理。
4. **實體還車與帳務結清分離。** 車已回場就釋放車輛；未付追加費用進入應收待辦。
5. **法律規則依契約類型。** 小客車規則不得無條件套用到機車；缺少合法規則時轉人工審查。
6. **外部服務失敗可恢復。** OCR、圖檔、Email、退款皆有處理中、成功、失敗與重試狀態。
7. **敏感資料最小化。** 正式證件圖檔不放 `localStorage`；前端只做開發用儲存模擬與介面契約。
8. **狀態不只靠顏色。** 所有警示同時使用文字、圖示與清楚的恢復方式。

## 3. 採用方案：分域工作流

不把所有欄位塞進 `RentalBooking`，也不在 MVP 引入完整事件溯源。以訂單為核心，將會重複、版本化或有獨立生命週期的資料拆成子模型：

```text
Member ── IdentityDocument / DriverCredential
   │
   └── RentalBooking ── PaymentRecord
                    ├── ChargeAdjustment
                    ├── ContractVersion
                    ├── HandoverRecord
                    ├── CancellationCase
                    ├── ReminderStatus
                    └── AuditEntry

Member ── CustomerCreditLedgerEntry
```

每個 UI 元件只透過 store/service 存取 repository。未來把本地 repository 換成 API 時，不重做流程與表單。

## 4. 核心資料與狀態

### 4.1 訂單履約狀態

建議的新狀態：

```text
reserved → in_progress → completed
    └───────────────→ cancelled
```

- `reserved`：訂單已成立但尚未取車，不代表已付款。
- `in_progress`：已完成取車交付。
- `completed`：車輛已實際歸還；仍可能有應收未結。
- `cancelled`：取消完成；退款仍可處理中。

既有 `pending_payment` 遷移成 `reserved` 加上由付款紀錄推導的「未付訂」。既有 `confirmed` 遷移成 `reserved`。取車資格不是另一個永久狀態，而是即時計算的 readiness 結果。

### 4.2 付款紀錄與推導狀態

每次收款保存：

- 訂單、金額、方式、用途（訂金／尾款／追加費用）
- 收款時間、經手人、備註
- 現金、信用卡、LINE Pay、銀行轉帳或保留金折抵
- 銀行轉帳的後五碼
- 模擬／待確認／已確認／失敗／作廢狀態

同一張訂單允許混合付款。畫面顯示每筆交易及「混合付款」，不以單一 `paymentMethod` 覆蓋歷史。

金額定義：

```text
最新應付總額 = 原訂單報價 + 已確認費用調整
淨實收 = 已確認收款 + 保留金折抵 - 已完成退款
待收餘額 = 最新應付總額 - 淨實收
```

付款狀態由金額推導：

- `deposit_due`：尚未達訂金門檻。
- `deposit_paid`：已達訂金門檻，但仍有尾款。
- `paid_in_full`：待收餘額為 0。
- `additional_payment_due`：原先已結清，因逾時、能源或其他調整重新產生餘額。
- `overpaid`：淨實收高於最新應付總額，需退款或轉保留金。

小客車訂金預設不得超過總租金 30%。車種或契約規則未設定時不可自行猜測。

### 4.3 會員、證件與駕駛資格

會員增加：

- Email
- 承租人類型：本國人、外國旅客、持居留證者
- 國籍、出生日期、地址
- 身分證明文件與駕駛資格的目前版本

證件模型支援：

- 台灣身分證、護照、居留證
- 台灣駕照、外國正式駕照、國際駕照、外國國際駕照簽證
- 文件號碼、發照國、效期、准駕類別原文與標準化車種
- 原國駕照、國際駕照、簽證頁及必要正反面圖檔參照
- OCR 狀態、信心分數、人工確認時間與確認人
- 互惠資格：待查核、符合、不符合、需人工審查
- 合法使用截止日與本次租用車種相符結果

會員層保存可重用文件；訂單保存本次使用的版本參照與文字快照，避免日後更新會員資料而改動舊合約。

### 4.4 合約版本

訂單成立時產生合約草稿，帶入：

- 出租人與承租人資料
- 車牌、車型及車輛資料
- 租期、取還車地點
- 租金、訂金、保險、配件與計價明細
- 取消、逾時、能源與其他已揭露規則
- 取還車紀錄需要的欄位

重大異動會產生新版本並使原簽署版失效：

- 承租人或駕駛人
- 車輛
- 租期或地點
- 租金、保險或其他契約核心內容

已簽署版本不可覆寫。取車時必須簽署最新版本。前端 MVP 提供預覽與簽名操作；正式 PDF、雜湊與簽署證據由後端接手。

### 4.5 取還車與費用調整

取車與還車各保存：

- 實際時間、里程
- 汽油車／機車的八分格油量
- 電動車的電量百分比
- 儀表與車況照片參照
- 操作人、承租人確認與備註

逾時規則放在定價方案：

- 免費寬限分鐘數
- 計費單位分鐘數
- 每單位逾時費
- 單日費用上限
- 是否允許人工調整及調整原因

能源補繳規則依車輛或車型設定：

- 每缺一格油量的費率，或每缺 1% 電量的費率
- 可選固定處理費

系統只先試算；人員確認後才建立 `ChargeAdjustment`。每次人工調整保存原試算、最終金額、理由、操作人與時間。

## 5. 新增訂單 UX

新增訂單採單一工作流，分成五段：

1. **租期與車輛**：選日期、時間、地點與車輛；即時檢查衝突並產生報價。
2. **承租人與駕駛資格**：搜尋既有會員或新增；依身分類型顯示動態證件欄位。
3. **費用與付款**：顯示租金、保險、配件、訂金上限；可連續新增多筆收款。
4. **合約**：產生草稿、預覽，可當場簽名或稍後在取車前完成。
5. **確認建立**：列出所有尚未完成的項目，避免把「已建單」誤解成「可交車」。

相機／OCR UX：

- 可開啟相機或選擇檔案。
- 顯示預覽、重拍、處理中、成功、低信心與失敗。
- OCR 不直接靜默覆寫欄位；新值和既有值衝突時逐欄確認。
- OCR 失敗保留照片與人工已輸入內容，可直接改為手動完成。
- 本輪 OCR 是 adapter 模擬，不宣稱為正式辨識功能。

## 6. 訂單工作區與首頁清單

### 6.1 回應式大型 dialog

完整訂單使用大型回應式 dialog，不限於現有 440px：

- 桌面：`width: 80vw`。
- 複雜訂單工作區：`max-width: 1200px`。
- 單純新增／編輯：可使用 `max-width: 800px`。
- 中型螢幕：依可用空間縮至約 80–90vw。
- 手機：全螢幕 `100vw × 100dvh`。
- 內容區自行捲動，表頭、狀態與主要動作保持可見。

工作區分頁：

- 總覽與待辦
- 承租人／證件
- 收款與費用
- 合約版本
- 取車／還車
- 取消、退款與業者補救
- 操作紀錄

開啟的訂單與分頁同步到 URL query params。重新整理可恢復；瀏覽器返回鍵可關閉 dialog。dialog 保留焦點圈限、Esc、關閉後焦點返回；有未儲存內容時先提示。

### 6.2 首頁取車 tab

每筆顯示：

- 車牌、時間、承租人
- 付款狀態、待收餘額
- 證件查核與最新合約簽署狀態
- 「可取車」或具體阻擋原因

快捷操作：收款、修改、取消、檢視合約、辦理取車。完整處理仍開同一訂單工作區，不另做第二套規則。

### 6.3 首頁待還車 tab

每筆顯示：

- 車牌、預定還車時間、承租人
- 是否逾時與逾時多久
- Email 提醒排程／寄送狀態
- 預估逾時費與目前待收餘額

快捷操作：檢視、聯絡、辦理還車。還車完成後立即釋放車輛；未付追加費用顯示「已還車／應收未結」。

## 7. 取車阻擋與主管覆核

一般人員不得取車的情況：

- 未達訂金門檻
- 最新合約未簽署
- 必要身分文件或駕照缺失／過期
- 外國旅客互惠資格或准駕車種不符
- 本次尚未確認核對證件正本
- 車輛衝突、維修中或其他不可交付狀態

主管可覆核部分阻擋，但必須保存原因、操作人與時間。法律資格不符及車輛安全不可交付不應僅靠一般主管覆核放行，需由營運規則明確定義可覆核範圍。

非阻擋提醒包括 Email 缺少、OCR 信心偏低、證件即將到期與特殊備註。

## 8. Email 還車提醒

預設排程：

- 還車前 24 小時：完整日期、時間、地點與注意事項。
- 還車前 2 小時：短版提醒與聯絡方式。

訂單取消或完成後不寄。修改還車時間後取消舊排程並重排。前端顯示待排程、已排程、已寄送、失敗與缺少 Email；實際排程、寄送及重試由後端負責。

## 9. 顧客取消、退款與保留金

取消先選責任：

- 顧客主動取消
- 當日未到／未通知
- 天災、停航或其他不可抗力
- 業者無法履約
- 其他需主管判定

系統使用 Asia/Taipei 時區保存申請時間，以預定取車日計算提前日數，並快照當時的規則版本。

### 9.1 小客車顧客取消預設規則

| 取消通知時間 | 訂金退還比例 | 可沒收比例 |
| --- | ---: | ---: |
| 預定取車日 10 日前 | 100% | 0% |
| 7～9 日前 | 50% | 50% |
| 4～6 日前 | 40% | 60% |
| 2～3 日前 | 30% | 70% |
| 前 1 日 | 20% | 80% |
| 當日或未通知 | 0% | 100% |

退款公式：

```text
可退金額 = 訂金 × 命中退還比例
         + 訂金以外已預付租金
         - 合法且已核准的退款手續費
```

付款紀錄必須能區分訂金與其他預付款，避免把全額付款都當成可沒收訂金。

不可抗力致契約不能履行時全額退款，手續費固定為 0。機車不直接套用此表；缺少經確認規則時轉人工審查。

### 9.2 退款手續費

- 欄位範圍 0～100 元，預設 0。
- 填寫 30～100 元時要求理由與主管確認。
- 顯示成獨立明細，不藏入退款淨額。
- 不可抗力、業者責任或其他依法應全額退還情況不可自動扣除。
- 正式使用前由營運／法務確認契約已充分揭露且不低於法定權益。

### 9.3 保留金

顧客可選：原方式退款、全部轉保留金、部分退款加部分保留金。轉換前必須取得明確同意。

保留金預設 12 個月，到期前 30 天提醒；主管可展期且保存理由。帳本保存來源訂單、建立額度、已使用、剩餘、到期日與每次異動。

## 10. 業者責任與服務補救

業者責任原因包括車輛故障、超賣、人員調度失誤與其他可歸責事由。

流程不是先取消，而是依序救單：

1. **同級調車**：重新檢查可用性並產生新版合約。
2. **免費升等**：顧客價格不增加，價差記為業者吸收。
3. **合作同業轉單**：記錄合作業者、替代車輛、外部報價、差額與顧客同意。
4. **補救失敗或顧客不同意**：進入業者責任取消。

小客車法定試算：

- 已收定金：返還原定金，另加同額賠償，合計定金兩倍。
- 未收定金：以約定總租金一倍進入賠償流程。
- 涉及業者故意或顧客提出其他損害證明：轉主管／法務審查，不由一般櫃檯直接結案。

上述責任不以取車當日或前一日為限。通知時間影響緊急程度和善意補償，但不縮減基本責任。

額外補償獨立記錄：

- 計程車車資補貼：金額、憑證、核准人。
- 折價券或額外保留金：標示為善意補償。

善意補償不得自動抵銷依法應退或應賠的現金。業者責任案件不得扣退款手續費，也不得強迫轉成保留金。

## 11. 外國旅客駕駛資格

系統不得以單一「是否有國際駕照」判斷合法性。至少考慮：

- 發照國／地區是否與台灣互惠
- 使用外國正式駕照或國際駕照的合法路徑
- 入境日期、停留期間與是否需辦理國際駕照簽證
- 原駕照、國際駕照、護照／居留證件效期
- 准駕車種是否與本次汽車或機車相符

互惠清單與合法使用截止日由可版本化的規則服務判斷，前端不寫死國家名單。資格不明顯示「需人工審查」，不可自動視為通過。

官方依據：

- [道路交通安全規則第 55、55-1 條](https://www.mvdis.gov.tw/webMvdisLaw/LawArticle.aspx?LawID=A0003100)
- [交通部公路局外國國際駕照簽證說明](https://www.thb.gov.tw/cp.aspx?n=96)
- [交通部公路局外國人用路手冊](https://ws.thb.gov.tw/Download.ashx?icon=..pdf&n=6aeV6aeb5Lq65omL5YaK5pu05paw5LqM54mILnBkZg%3D%3D&u=LzAwMS9VcGxvYWQvNDM2L3JlbGZpbGUvMTI4MjMvMjE3MTg2Lzg2Yzg4ODVmLTk1Y2UtNGFmOC04M2UyLWVmYWYzYzI2Y2VhOS5wZGY%3D)

## 13. 風險與防護措施

| 風險來源 | 嚴重度 | 防護措施 |
| --- | --- | --- |
| 付款與履約狀態混用 | 高 | 分離狀態，以交易紀錄推導付款結果 |
| 小客車規則誤套機車 | 高 | 規則依契約／車種版本化；缺規則轉人工審查 |
| 外國駕照或准駕車種不符仍交車 | 高 | 動態資格查核、取車阻擋、人工審查紀錄 |
| 敏感圖檔存放不安全 | 高 | 正式圖檔只交後端私有儲存；本地方案明確標示開發用途 |
| 修改訂單仍沿用舊合約 | 高 | 核心異動自動使簽署版失效並產生新版本 |
| 重複收款、退款或合約建立 | 中 | 送出鎖定、冪等鍵介面與明確結果狀態 |
| OCR 結果被誤認為已核對 | 中 | 顯示信心與來源；必須人工確認 |
| 大型 dialog 在窄螢幕溢出 | 中 | 80vw／最大寬度、手機全螢幕、焦點與捲動驗證 |
| 警示過多造成疲乏 | 低 | 阻擋／緊急／提醒三級，只呈現具體下一步 |

## 14. 錯誤處理與可存取性

- 所有非同步功能都有 loading、empty、success、error 與 retry。
- 錯誤訊息說明發生什麼、資料是否已保存、使用者下一步能做什麼。
- 關鍵操作避免重複送出；取消、退款、主管覆核與合約失效都需明確確認。
- dialog 可用鍵盤完成，焦點可見，關閉後回到觸發列。
- 手機全螢幕模式使用 `100dvh`，避免瀏覽器工具列造成內容被遮住。
- 狀態晶片、警告與成功訊息皆有文字，不以顏色作唯一訊號。
- 相機不可用時自動提供一般檔案選擇，不阻斷人工流程。

## 15. 測試與驗收

### 15.1 Domain 單元測試

- 付款狀態、混合付款、溢收與追加費用。
- 訂金上限及訂金／其他預付款分配。
- 取消 10、9、7、6、4、3、2、1、0 日所有邊界。
- 不可抗力全額退、手續費限制、業者加倍返還。
- 保留金建立、折抵、到期與展期。
- 合約重大異動失效規則。
- 取車阻擋與主管覆核範圍。
- 逾時計費的寬限、級距、上限及人工調整。
- 油量八分格與電量百分比補繳。

### 15.2 Store 與流程測試

- 建單、會員重用、證件快照、付款與合約版本。
- 取車與還車，包含車已回場但帳款未結。
- 顧客取消、不可抗力、退款、混合退款／保留金。
- 業者同級調車、免費升等、合作同業轉單及救單失敗。
- Email 改期重排與取消訂單停止寄送的 adapter 契約。

### 15.3 元件與互動測試

- 本國／外國／居留證的動態欄位。
- 相機不可用、OCR 低信心、失敗與人工校正。
- 連續新增付款、轉帳後五碼條件欄位、重複送出防護。
- 未儲存提示、Esc、焦點圈限、關閉後焦點返回。
- 警示具有文字與可執行的恢復動作。

### 15.4 RWD 與真實瀏覽器驗收

在 1440、1024、768、390、320px 驗證：

- 80vw dialog 與 800／1200px 上限。
- 手機全螢幕、長內容捲動、固定表頭／主要動作。
- 無橫向溢出，長姓名、外國證件、金額與備註可換行。
- 首頁取還車清單可讀，快捷操作不誤觸。
- 圖片預覽使用合理尺寸，非當前分頁延遲載入，開啟 dialog 無明顯跳動。

## 16. 明確不在本輪前端範圍

- 真實金流授權、請款、刷退或 webhook。
- 正式 OCR、雲端圖檔、病毒掃描與文件保存政策。
- 實際 Email 排程與寄送。
- 正式外國駕照互惠資料同步。
- 具法律證據力的合約 PDF、簽名驗證與不可竄改稽核。
- 與合作同業自動交換庫存或訂單。

這些項目全部記錄在後端 hand-off，前端只提供介面、狀態與可測的模擬實作。
