# 租車營運工作流：後端 Hand-off

**日期：** 2026-09-18
**上游設計：** `docs/plans/2026-09-18-rental-operations-workflow-design.md`
**目的：** 集中記錄前端 MVP 無法安全或可靠完成、必須由後端與營運共同承接的能力。本文不是 API 最終規格；實作前仍需確認身分驗證、權限、資料庫、儲存、郵件與金流供應商。

## 1. 交接原則

- 前端不得成為金額、資格、排程或稽核的唯一可信來源。
- 所有具副作用的寫入都需身分驗證、授權、冪等與伺服器時間。
- 圖檔、OCR 結果、法規規則、付款、退款、合約與 Email 都需要可追蹤狀態，而非只回傳成功或失敗。
- API 回應需提供可公開給使用者的錯誤代碼與恢復方式，避免前端解析內部錯誤訊息。
- 所有金額使用整數新台幣；所有時間以 UTC 保存並帶時區語意，營運規則以 Asia/Taipei 計算。

## 2. 身分、權限與稽核

後端需提供：

- 員工登入與角色：一般櫃檯、主管、財務、營運、系統管理員。
- 細粒度權限：取車覆核、費用調整、取消規則覆蓋、退款核准、保留金展期、業者賠償。
- 稽核紀錄：操作者、時間、動作、目標、異動前後值、原因、來源 IP／裝置資訊。
- 稽核紀錄不可由一般使用者覆寫或刪除。
- 主管覆核需保存覆核人的獨立身分，不接受前端只送 `isApproved: true`。
- 敏感欄位遮罩與最小權限查詢，例如銀行後五碼、證件號碼及圖檔。

## 3. 證件圖檔儲存

### 3.1 上傳與存取

- 私有 object storage；禁止公開永久 URL。
- 由後端產生短效 signed upload/download URL，並驗證檔案用途、大小、MIME type 與副檔名。
- 上傳完成後以 callback／complete endpoint 建立正式文件紀錄。
- 圖檔需加密保存，傳輸使用 TLS。
- 進行惡意檔案與病毒掃描；未通過前狀態為 `quarantined`，不可供 OCR 或一般員工查看。
- 產生適合列表／預覽的縮圖，避免前端每次下載原始大圖。

### 3.2 文件資料

每份文件至少保存：

- `documentId`、會員、文件類型與版本
- 正反面／資料頁角色
- storage key、原始檔名、MIME、大小、checksum
- 上傳者、建立時間、掃描狀態
- OCR 狀態與目前結果版本
- 取代的前一版本與使用中的訂單參照
- 保留／刪除期限與法律保留原因

### 3.3 個資生命週期

- 與營運／法務定義蒐集目的、告知與同意文字。
- 定義租賃關係結束後的保存期限、刪除或去識別化流程。
- 會員要求查詢、更正、停止利用或刪除時，需處理仍受契約／法規保存要求約束的例外。
- 記錄每次圖檢視與下載，避免敏感文件被無聲存取。
- 備份、還原與刪除流程需覆蓋 object storage 與衍生縮圖。

## 4. OCR 服務

後端負責選擇供應商或模型並提供統一介面。至少支援：

- 台灣身分證
- 台灣汽車／機車駕照
- 護照資料頁
- 外國駕照與國際駕照的基本欄位；無法可靠辨識時回人工審查

建議工作流：

```text
uploaded → scanning → queued → processing
         → succeeded / low_confidence / failed / manual_review
```

回應內容：

- 欄位值、欄位級 confidence、文件類型判定
- 原始 OCR provider、model/version、語言與處理時間
- 候選值或未識別原因
- 不直接覆寫人員已確認資料；人工修正建立新結果版本

需處理：

- 重複請求的冪等鍵
- 供應商 timeout、rate limit、部分欄位成功與重試
- OCR 資料是否會被供應商保存或用於模型訓練
- 敏感資訊避免出現在一般 application log

## 5. 外國駕照與互惠規則

後端／營運需維護可版本化規則資料，而非讓前端寫死國家清單：

- 國家／地區與台灣的互惠狀態
- 可接受證件路徑：外國正式駕照、國際駕照、翻譯文件、簽證或台灣駕照
- 短期停留與超過 30 日的處理
- 車種／准駕類別對應
- 生效日、失效日、官方來源 URL、最後確認人與確認時間

資格判定 API 輸入應包含國籍、發照國、入境日期、租期、各證件效期與准駕類別；輸出應包含：

- `eligible`、`ineligible` 或 `manual_review`
- 合法使用截止日
- 缺少文件與不通過原因
- 使用的規則版本與來源

法律或互惠資料不確定時必須回 `manual_review`，不得推測通過。

## 6. Email 排程與寄送

預設事件：還車前 24 小時與 2 小時。

後端需支援：

- 建單或補上 Email 後建立排程。
- 修改還車時間時取消舊排程並重建。
- 取消或完成訂單時取消尚未寄送的任務。
- template version、locale、收件人、預計寄送時間與訂單快照。
- provider message id、嘗試次數、最後錯誤與 delivered／bounce／complaint webhook。
- 重試與 dead-letter queue；不可因 worker 重跑寄出重複郵件。
- 退信或永久失敗回寫前端可處理的狀態。

建議狀態：

```text
not_scheduled / scheduled / sending / sent / delivered
failed_retryable / failed_permanent / cancelled
```

## 7. 付款、退款與冪等

本輪前端只記錄人工確認付款。未來接金流時，後端需保存不可覆寫的交易帳本：

- payment intent／transaction id
- 訂單、金額、幣別、方式、用途
- provider、授權／請款／失敗／取消狀態
- 銀行轉帳後五碼及實際入帳確認
- 原始 provider reference 與 webhook event id
- 建立人、確認人與時間

所有收款與退款 endpoint 需使用 idempotency key。Webhook 必須驗簽、去重並容忍遲到、重送與亂序。

退款需能對應原始交易，保存：

- 取消案件與計算快照
- 應退本金、法定賠償、其他補償、手續費與最終退款
- 原路退回／人工匯款／現金／保留金等處置
- provider refund id、狀態、失敗原因與完成時間
- 財務核准及操作人

後端必須重新驗證前端傳入的金額、取消規則與可扣手續費，不可相信前端計算結果。

## 8. 取消規則與法律版本

取消規則資料需版本化：

- 契約類型與適用車種
- 生效期間
- 訂金上限
- 提前日數級距與退款比例
- 不可抗力處理
- 業者責任賠償方式
- 手續費允許範圍
- 官方來源及法務確認紀錄

每個 `CancellationCase` 保存使用的規則版本與輸入快照，避免未來改規則後舊案件被重新計算。

小客車預設依現行契約範本；機車規則需由營運／法務另行確認。退款手續費預設 0，不可抗力與業者責任不得自動扣除。

## 9. 業者責任、合作同業與補償

後端資料需區分：

- 法定退款／賠償
- 顧客可證明的其他損害
- 計程車等費用補貼
- 善意折價券或額外保留金
- 合作同業轉單的對外成本與業者吸收差額

合作同業初期可由員工人工記錄。若未來串接：

- 同業身分、庫存確認、報價、接受／拒絕狀態
- 顧客同意與資料分享範圍
- 外部訂單編號與取消同步
- 對帳、差額、發票及個資委外契約

善意補償不可在帳務上抵銷法定現金責任，除非另有明確且可證明的顧客合意。

## 10. 保留金帳本

保留金不可只存在會員的單一餘額欄位。後端需使用 ledger：

- credit issued、redeemed、expired、extended、reversed
- 來源取消案件或善意補償
- 原始額度、每次使用額、剩餘額
- 建立、到期與展期時間
- 顧客同意證據
- 操作人與核准人

預設效期 12 個月，到期前 30 天建立提醒。展期不可覆寫原到期日，需新增異動紀錄。並發折抵需交易鎖或等效機制，避免同一額度被重複使用。

## 11. 合約、PDF 與電子簽名

前端 HTML 預覽不是正式契約證據。後端需負責：

- 由不可變訂單快照產生 PDF。
- 合約 template version、條款版本與文件 hash。
- 承租人及出租人簽名圖檔／簽署資料的私有儲存。
- 簽署時間、簽署人身分、同意文字版本、裝置／IP 等可接受的證據欄位。
- 重大資料修改後使舊版本標記 superseded，並產生新草稿。
- 已簽署文件不可覆寫；更正以新版本處理。
- 提供短效下載連結與存取稽核。

正式電子簽名證據標準與保存期限需由法務確認。

## 12. 逾時與能源補繳

後端應成為正式計算來源，前端試算僅供即時 UX：

- 逾時寬限、計費單位、單位費率、每日上限及規則版本
- 小客車與機車不同契約限制
- 取還車實際時間、油量／電量與照片證據
- 自動試算、人工確認、最終調整、理由與核准
- 調整加入應收後重新計算餘額

相同輸入必須產生可重現的計算結果，並保存使用的定價／規則版本。

## 13. 前端期待的服務介面

實際命名可調整，但需涵蓋以下能力：

```text
DocumentStorageGateway
  createUpload(), completeUpload(), getPreviewUrl(), deleteDocument()

OcrGateway
  submit(), getResult(), retry(), confirmCorrection()

DriverEligibilityGateway
  evaluate(), getRuleVersion()

ReminderGateway
  schedule(), reschedule(), cancel(), getStatus()

PaymentGateway
  recordManualPayment(), createPayment(), confirmPayment(), getLedger()

RefundGateway
  quoteCancellation(), submitRefund(), getRefundStatus()

ContractGateway
  createDraft(), renderPreview(), sign(), supersede(), getDownloadUrl()

AuditGateway
  appendReasonedAction(), queryTimeline()
```

回應應包含穩定狀態 enum、錯誤 code、是否可重試與 correlation id。

## 14. 非功能需求

- **安全：** OWASP 常見風險、輸入驗證、速率限制、秘密管理、加密與權限測試。
- **隱私：** 個資告知、目的限制、資料最小化、保存與刪除政策。
- **可靠性：** queue retry、dead-letter、冪等、監控與告警。
- **可觀測性：** correlation id、結構化 log、metrics；敏感資料不得進 log。
- **備援：** 資料庫與 object storage 的備份、還原及演練。
- **效能：** 圖片縮圖、分頁查詢、避免一次載入全部證件或合約。
- **相容性：** API schema 版本化，前端可在 rollout 期間容忍新舊欄位。

## 15. 後端驗收情境

至少驗證：

1. 同一付款／退款請求重送不會產生第二筆交易。
2. 修改還車時間後舊 Email 不會寄出，新排程正確建立。
3. 訂單取消或完成後所有未寄提醒取消。
4. 私有證件 URL 過期且無權限者無法存取。
5. OCR timeout 可重試，人工修正不被晚到結果覆蓋。
6. 外國駕照規則版本可回溯，未知條件回人工審查。
7. 小客車與機車使用不同取消規則，舊案件不受新版本影響。
8. 業者責任取消不扣手續費，法定賠償與善意補償分開。
9. 保留金並發折抵不會成為負數或重複使用。
10. 修改核心訂單資料後舊合約不可再作為可取車依據。
11. 主管覆核保留身分、原因、前後值與時間。
12. 敏感資料不出現在一般 log、錯誤追蹤或分析事件中。

## 16. 上線前需要營運／法務確認

- 小客車與機車各自使用的契約與取消規則版本。
- 退款手續費是否可收、揭露方式及不得收取的情況。
- 保留金 12 個月效期、展期、到期提醒及未使用餘額處理。
- 外國駕照人工審查 SOP 與官方資料更新責任人。
- 電子簽名證據、契約保存年限及顧客取得副本方式。
- 身分證、護照、駕照圖檔的保存與刪除期限。
- 業者故意、其他損害、合作同業轉單與額外補償的核准層級。
- Email 模板、寄送時點、退訂／必要通知的分類。

上述項目未確認前，後端不應用預設值替營運作法律判斷。
